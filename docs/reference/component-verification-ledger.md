# Component verification ledger

This ledger covers the component rows in the [component coverage matrix](component-coverage.md). The [Phase 0/1 master inventory](m3e-master-component-inventory.csv) provides a 38-entry, finer-grained catalog; the [source-evidence ledger](m3e-source-evidence-ledger.csv) preserves its per-entry provenance and audit limitations. This dated evidence snapshot is not a conformance statement or a substitute for component-specific visual, accessibility, or platform validation.

## Evidence and status rules

- **Material source check — 2026-10-24:** each linked official component URL in the tables below returned HTTP 200 when checked. The check extracted the page title and HTML description metadata (the brief purpose summary recorded below). It did **not** inspect the complete interactive page, its illustrations, exact dimensions, tokens, motion, or all state specifications. Metadata only confirms broad page identity/purpose; it is not evidence of full visual guidance.
- **Flutter SDK check — repository snapshot:** the prior repository check reports **Flutter 3.47.7 stable**, framework revision `abaf9c5237` (2026-10-08), and **Dart 3.13.5**, with SDK source inspected at `C:\flutter`. The supplied Phase 0/1 audit did not independently rerun that check. The inventory marks API/test evidence as repository-reported where applicable; this is API availability evidence, not M3/M3 Expressive visual equivalence.
- **Coverage labels:** **API verified** means the named Flutter Material class/function exists in the SDK above. **Composition only** means the design pattern has no direct stock Flutter Material widget asserted here. **No direct API** means no equivalent component widget was verified. **Unverified** means the relevant design behavior, local implementation, or platform treatment was not established. **Visual test** means only that the named repository fixture is compared against a Flutter widget-test golden.
- **State codes:** each state cell lists all nine state dimensions in this fixed order: `D` default, `H` hover, `F` focus, `P` pressed, `S` selected, `Dis` disabled, `L` loading, `E` error, `X` expanded/dismissed. `T` = exercised by a widget test or represented in a named golden; `U` = applicable but not tested; `N/A` = not applicable to the mapped component/pattern. A visual default in a golden does not mean hover/pressed/focus visuals were validated.
- **Recommendation versus requirement:** practical test suggestions in this repository are recommendations, not claims about official M3 requirements. Material intent below is limited to what the checked metadata expressly says.

## Visual and interaction test coverage ledger

The visual tests are `flutter_test` widget tests comparing captured Flutter render output to checked-in PNG goldens. They are deterministic widget-level fixtures, not browser/device screenshots. Flutter widget tests use the Ahem test font for fallback glyph rendering; in the committed PNGs, text appears as block glyphs. These goldens can flag geometry, color, and layout regressions in this renderer, but they do not validate real glyph typography, browser/device rendering, platform parity, or M3 Expressive visual conformance. The PNGs were inspected only for obvious fixture geometry clipping under this renderer. For official design imagery, use the [Material visual reference gallery](visual-reference-gallery.md) and its linked component pages; do not treat the test goldens as design examples.

No golden or widget test establishes platform parity or complete Material 3 / M3 Expressive conformance. Re-run these tests against the intended pinned SDK and add platform/assistive-technology validation for a specific app before relying on its behavior.
