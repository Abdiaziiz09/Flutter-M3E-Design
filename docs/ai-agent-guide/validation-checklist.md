# Visual, interaction, and accessibility checklist

For every relevant target/theme, record pass, fail, not applicable, or not tested.

- [ ] Typography uses intentional roles, readable wrapping, and respects text scaling.
- [ ] Colors use semantic roles; contrast and non-color state cues are checked.
- [ ] Shapes are consistent with component intent and do not clip content.
- [ ] Spacing and alignment express grouping and remain robust under localization/RTL.
- [ ] Surface hierarchy is clear; elevation is not the only cue.
- [ ] Component anatomy and source-backed variants match the applicable guidance.
- [ ] Disabled, focused, hovered, pressed, selected, loading, and error states are tested where relevant.
- [ ] Motion communicates change, handles interruption, and has a reduced-motion strategy.
- [ ] Semantics, labels, focus order, keyboard access, and screen-reader behavior are checked.
- [ ] Responsive behavior works at narrow, intermediate, wide, and resized constraints chosen for the app.
- [ ] Platform navigation, system UI, pointer/touch/keyboard, and window behavior are checked.
- [ ] Automated checks and visual comparisons are recorded with environment/version.

Do not treat automated screenshot equality as proof of usability or M3 Expressive conformance.
